# ADR-002: DBアクセス層に sqlc を採用する

## メタデータ

| 項目 | 内容 |
|---|---|
| 対象ドメイン | バックエンド／DBアクセス |
| 変更種別 | ライブラリ選定 |
| 可逆性 | 条件付き可逆（移行コストはあるが置き換え可能） |
| 影響範囲 | 広域（全DBアクセス層） |
| 領域分類 | 非センシティブ（DBスキーマの破壊的変更はセンシティブ扱いだが、アクセス層の選定は非センシティブ） |
| エスカレーション | 不要 |
| AIの当初判断 | sqlc 採用。生SQL不可、ORM不採用 |
| 人間の最終判断 | 追認（AI_DEVELOPMENT_GOVERNANCE.md に明記された方針と一致） |
| 状態 | 有効 |
| 自律実行カウンタ | 1 |

## 背景

Go の DBアクセス層として以下が候補となる。

- 生 `database/sql` — 型安全性がなく、AIが自律実行する際にSQLミスを検出しにくい
- GORM 等のORM — 抽象化が高く、生成クエリが不透明になる
- sqlc — SQLを書くとGoコードを自動生成する。型安全・コンパイル時検証が可能

## 決定

**sqlc** を採用する。

- `backend/db/schema.sql` にスキーマを定義
- `backend/db/queries/*.sql` にクエリを定義
- `sqlc generate` で `backend/internal/db/` に型安全なGoコードを生成
- 生成コードはコミット対象（変更差分をレビュー可能にする）
- スキーマ変更後は必ず `sqlc generate` を再実行する

## 結論

AIが自律的にDBアクセスコードを書く際、コンパイルエラーで誤りを即検出できる。
§2.1「検証の機械可読性」の要件を満たす。
